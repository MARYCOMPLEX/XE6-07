# 提案：私有模型提交审核

## 动机 / 用户故事

模型所有者需要从“我的模型”提交一个私有模型供审核，但不应因提交而直接公开，也不应重复上传已有资产。

## 目标用户

- 希望发布私有模型的模型所有者
- 后续处理审核申请的管理员

## 本期范围

本期做：从“我的模型”选择私有模型；填写标题、描述、分类、授权方式和可选标签；复用已有模型文件、封面和预览；检查封面、可用 3D 预览、STL 或 3MF、必填字段；提交后状态变为审核中并锁定本次信息和模型版本。

本期明确不做：管理员审核、审核通过/驳回/下架、公共模型库、搜索、收藏、举报、Fork、复杂版权识别、专业打印参数、G-code 上传或公开、多份草稿和发布历史。

## 关键决策与依据

提交审核是从私有到审核中的独立状态转换，不等于公开。模型文件、封面和预览复用已有资产；同一模型不能产生多份审核申请；新版本不得静默替换正在审核的版本。每一种授权方式必须能判断下载、Fork/二创、原作者署名和相同授权方式要求。

## 验收标准

### 例子 1：完整私有模型提交

- 现状：用户不知道发布所需信息和资源是否齐全，且可能重复上传已有资产。
- 提议后的行为：所有者填写发布信息并完成预检查。
- 验收：页面逐项显示封面、预览、可下载文件和字段检查；提交成功后模型为审核中，提交信息和版本可查看且普通用户不可见；刷新或重新登录后状态保持准确。

### 例子 2：缺失项或非所有者

- 现状：缺少文件或权限错误可能造成错误提交。
- 提议后的行为：明确展示每个缺失项，并阻断无权请求。
- 验收：缺少封面、预览、STL/3MF 或必填字段时按钮不可用且每项提示具体；非所有者不创建申请；授权结果可供后续 Fork 判断。

### 例子 3：重复和失败请求

- 现状：重复点击或网络重试可能产生多份审核申请。
- 提议后的行为：同一模型在审核中不可再次提交，失败不改变模型状态。
- 验收：重复点击、网络重试或审核中再次提交不产生重复申请；提交失败时模型保持原私有状态；审核中信息和版本不会被后续修改静默替换。
