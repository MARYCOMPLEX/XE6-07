# 提案：切片服务适配与回退策略

## 动机 / 用户故事

平台应向用户提供稳定的切片结果，而不让业务流程依赖某一切片器 CLI 的参数、日志或失败格式。

## 目标用户

- 需要把通过审计模型转换为打印计划的用户
- 维护切片服务和设备适配的工程人员

## 本期范围

本期做：定义 `SlicerAdapter`；接收通过可打印审计的 `AssetRevision`；支持省时间、省材料、稳妥模板；输出 `SliceJob` 和 `SliceReport`；优先 Bambu Studio CLI，不可用、失败或设备不匹配时回退 OrcaSlicer 或 PrusaSlicer；几何变化后使旧结果失效。

本期明确不做：真实打印机接入、LLM 生成或修改 G-code、复杂多色和工业级参数优化。

## 关键决策与依据

以适配器隔离不同 CLI，结果统一为内部报告；回退只在主切片器不满足条件时发生，并留下结构化错误，避免业务层直接解析原始输出。

## 验收标准

### 例子 1：主链路与统一结果

- 现状：切片器输出格式直接泄漏给业务功能。
- 提议后的行为：通过审计的版本以“稳妥”模板进入适配器。
- 验收：结果记录耗时、耗材、支撑、风险、产物位置和所用切片器。

### 例子 2：主链路失败回退

- 现状：Bambu CLI 不可用时任务没有统一处理。
- 提议后的行为：记录失败原因，并按策略尝试 Orca 或 Prusa。
- 验收：失败和回退均有结构化状态；用户可观察最终所用切片器。

### 例子 3：非法版本与失效结果

- 现状：未审计模型或旧几何结果可能继续使用。
- 提议后的行为：未通过审计时阻断；几何变化后失效旧 `SliceJob`。
- 验收：不调用 CLI；旧切片和打印清单不能再提交。
