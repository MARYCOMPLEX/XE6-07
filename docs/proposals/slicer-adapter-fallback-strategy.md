# 提案：切片服务适配与回退策略

## 动机 / 用户故事

平台应向用户提供稳定的切片结果，而不让业务流程依赖某一切片器 CLI 的参数、日志或失败格式。

## 目标用户

- 需要把通过可打印性检查的模型转换为打印计划的用户
- 维护切片服务和设备适配的工程人员

## 本期范围

本期做：定义切片编排层与 `SlicerAdapter` 接口，屏蔽不同 CLI 的参数、日志和错误差异；接收通过可打印性检查的 `AssetRevision`；统一“省时间”“省材料”“稳妥”三类方案；编排 Bambu Studio CLI 主链路及 OrcaSlicer、PrusaSlicer 兜底；输出统一 `SliceJob`、尝试记录和 `SliceReport`；依据不可变输入绑定判断旧结果是否失效。

本期明确不做：真实打印机接入、LLM 生成或修改 G-code、复杂多色和工业级参数优化。

## 关键决策与依据

本提案是切片链路的编排总提案：任务创建、门禁与方案选择由 #90 细化；Bambu Studio CLI 主适配由 #120 细化；Orca/Prusa 回退与错误分类由 #91 细化；结果展示和版本失效由 #92 细化。本提案只定义这些能力之间的稳定契约和组合关系，不重复承担各子提案的内部实现。

以适配器隔离不同 CLI，结果统一为内部报告。只有 CLI 不可用、超时、进程异常退出或临时资源故障等可重试运行错误才能触发回退；可打印性检查失败、文件损坏、模型或设备 profile 不兼容、用户配置缺失等语义错误必须立即终止。所有候选尝试必须锁定同一 `modelRevisionHash`、方案及 `profileId/profileVersion`，不得在回退时静默改变输入。真实 CLI 与本地 mock 的配置边界必须在文档中说明。

## 基本概念与信息结构

- `SlicerAdapter`：接收统一切片输入并返回统一成功结果或结构化错误，不向业务层泄漏 CLI 原始格式。
- `SliceAttempt`：记录切片器及版本、输入绑定、开始和结束时间、结果、错误分类和失败原因。
- `SliceReport`：记录产物、预计时间、耗材、支撑、风险、最终切片器及版本，以及不可变输入绑定。
- 回退策略：按配置选择候选，但只对标记为可重试的错误继续下一个候选。

## 验收标准

### 例子 1：主链路与统一结果

- 现状：切片器输出格式直接泄漏给业务功能，调用方无法稳定消费报告。
- 提议后的行为：通过可打印性检查的版本以“稳妥”方案进入编排层。
- 验收：具有稳定 `SlicerAdapter` 接口与 mock 实现；结果写入内部 `SliceJob`/`SliceReport`，并记录耗时、耗材、支撑、风险、产物位置、所用切片器及版本和不可变输入绑定。

### 例子 2：主链路失败回退

- 现状：Bambu CLI 不可用时任务没有统一处理。
- 提议后的行为：可重试运行错误记录失败原因并按策略尝试 Orca 或 Prusa；语义错误立即终止。
- 验收：Bambu Studio CLI 不可用或超时时会尝试下一个候选；设备 profile 不兼容、文件损坏或用户配置非法时不触发回退；每次尝试均有结构化状态与可解释原因，用户可观察最终所用切片器。

### 例子 3：非法版本与失效结果

- 现状：未通过检查的模型或绑定旧输入的结果可能继续使用。
- 提议后的行为：未通过检查时阻断；模型内容哈希、方案/profile 或切片器版本变化后使旧结果失效。
- 验收：未通过检查时不调用 CLI；`modelRevisionHash`、`profileVersion` 或 `slicerVersion` 任一变化都会使旧切片与打印清单失效，并有测试覆盖；README 或 docs 说明本地 mock 与真实 CLI 的配置边界。

### 例子 4：总提案与子能力组合

- 现状：任务创建、主切片、回退和结果管理可能各自定义不一致的字段与状态。
- 提议后的行为：四类子能力通过本提案规定的统一输入、错误分类和 `SliceReport` 契约组合。
- 验收：#90 创建的任务可被 #120 主适配消费，#91 可依据同一错误分类决定是否回退，#92 可依据同一不可变输入绑定判断结果有效性；业务层无需解析任一 CLI 原始输出。
